# 写作 voice 标准（长期默认）

Joy 2026-05-30 对齐。以后每篇默认按这五条，不用再提。
前几篇（尤其章节结尾）反复飘回说教，所以这次把反面例子写死，照着自查。

## 五条

1. **标题让人一看就懂。** 直接点出是什么事，不靠绕弯的反差。读者看标题不该还要猜在说哪个东西。
   - 反例：发明这个榜的人，自己把它弃用了（读者不知道哪个榜）。
   - 正例：最有名的 AI 编程榜，作者自己停用了。

2. **能用中文就用中文。** 只有没有通用中文叫法的产品名 / 榜名才留英文（SWE-bench、Claude、GPT、OpenAI、Anthropic、GitHub）。常见词一律中文：
   - scaffold→脚手架 · eval→评测 · benchmark→跑分 / 榜 · demo→演示 · agent→AI / 智能体 · ground-truth→标准答案 · code review→代码评审 · harness→尽量不用，要用给中文。

3. **句子短、说人话，一句讲一件事。**

4. **少破折号（——）、少双引号（“”）。** 能直说就直说。不用引号包概念，不用破折号当连接。

5. **不说教。** 事实摆清，观点一句话直接下。禁止：
   - 编号建议清单（第一第二第三第四）；
   - 口诀式收尾（下次别问 X 要问 Y / 记住 / 你应该）；
   - 金句升华收尾。
   - 结尾停在事实或观察上，不向读者喊话。

## 反面例子（都来自真实草稿，别再犯）

- 说教清单：第 5 章排「第一别用综合分、第二自己跑、第三搭评测、第四连版本一起读」 → 改成「认真测过的人最后大都这么做」的叙述。
- 口诀收尾：「下次看到发布会屠榜，别急着记那个百分比，问一句……」 → 删，结尾停在事实。
- 双引号包概念：我们 87 他们 85 / 涨幅有水分 / 谁的模型考分高 → 拆掉重说，不加引号。
- 破折号当连接：脚手架——决定怎么喂题 → 用句号或括号断开。
- 堆英文：scaffold / eval / benchmark / demo 满篇 → 全中文。

## 开头（Joy 2026-05-31）

- **别用具体年份起手**（「2023 年，……」读着奇怪）。要交代时间用「前几年 / 这两年」这类。
- **单刀直入**：直接把读者放进场景（「给产品加个 AI 功能，做法几乎是固定的：……」），不绕。
- **读者不是小白，术语点到即止**：不要把「把文档切成小块 / 转成一串数字叫向量」这种基础流程铺开解释。听过的词直接用，一句话能带过就别展开。
  - 反例：花一整段解释「向量是什么、RAG 怎么工作」。
  - 正例：「先把资料转成向量存起来，提问时再把最相关的几段捞出来喂给大模型」——一句话带过。

## 适用范围

所有期默认。各期 notes 的「风格约束」以本条为准；旧 notes 里更笼统的 voice 描述被本条覆盖。
体裁仍是报道 + 评判：摆事实、给判断，steelman 不少于批判，论点大方归属。
