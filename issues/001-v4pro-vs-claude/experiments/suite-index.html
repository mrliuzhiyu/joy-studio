为什么做这个

DeepSeek V4-Pro 是家喻户晓的"国内顶级推理大模型"，但对前端/代码生成这类"不那么像数学题"的任务到底能做到什么程度，少有人把实物做出来并排比。这次做一次真实、可验证、不手下留情的同题三连评测：同一个 prompt 同时发给 V4-Pro 和 Claude Opus 4.7，每家各产出一份可直接用浏览器打开的 HTML，然后在同一篇文章里把它们放到一起。

三道题刻意选了三条差异很大的轴：算法可视化（归并排序）考"动画 + 状态机 + 交互控制"；3D 数学渲染（洛伦兹吸引子）考"数值积分 + 投影 + 动效性能"；UI/UX 开放题（番茄钟）考"审美、产品化细节、持久化"。

V4-Pro 的调用参数本轮统一为 temperature=0.2~0.3，不传 max_tokens（踩坑记录见上一篇实验，传 8192 会把预算全让思维链吃掉）。三个请求并发下发，数据来自真实 API 响应。

题目全文 
做一个归并排序可视化网页。

要求：
1. 顶部有一个文本框（默认填 "38,27,43,3,9,82,10"）、一个"开始/重置"按钮、一个速度滑块（快-慢）。
2. 点击开始后动画展示 mergeSort 的分治过程：
   - 每一层递归横向展开，父数组向下分裂成两个子数组；
   - merge 阶段：两个子数组里正在比较的元素高亮橙色，选中后移动到上层对应位置；
   - 已完成排序的层用绿色标注。
3. 底部有"上一步 / 下一步 / 自动播放 / 暂停"四个按钮，支持单步观察。
4. 深色主题、干净排版、移动端可看。

单文件 HTML，内嵌 CSS+JS，不引用任何外部 CDN / 图片 / 字体。只输出完整 HTML（从 <!DOCTYPE html> 到 </html>）。

本题观察

  • 取态Claude 按"树的完整骨架 + 分步回放"的思路——一开始就把所有层的节点画出来，随步骤高亮/填色。V4-Pro 选了"增量构建"——按层逐步 DOM 追加，动画感更强。两种合法，各有侧重。
  • 视觉Claude 深色 + 黄色 accent（#fbbf24），节点间距紧凑，排版类似调试器；V4-Pro 深紫底 + 橙/绿/蓝三色分工，用大量 CSS 变量，排版更"产品级"。
  • 体量Claude 12.6 KB / V4-Pro 47 KB（约 3.7 倍）。V4-Pro 的 CSS 扩成了超 30 个 token 的设计系统；Claude 把所有样式压在 200 行内。
  • 思维链V4-Pro 本题花了 6 362 reasoning tokens，约占本题总预算的 40 %。思维链原文可点右下角链接查看。

题目全文 
做一个洛伦兹吸引子 3D 可视化网页。

要求：
1. canvas 上绘制洛伦兹吸引子轨迹：参数 σ=10, ρ=28, β=8/3；RK4 积分，步长 0.005，累计 15000 个点。
2. 轨迹颜色随时间从蓝 (#3b82f6) → 紫 (#a855f7) → 洋红 (#ec4899) 渐变；线宽约 1px；轨迹有发光效果（shadowBlur）。
3. 自动绕 Y 轴缓慢旋转；支持鼠标拖拽调整视角（yaw/pitch）；滚轮缩放。
4. 顶部小面板实时显示当前动画帧率 (FPS)、当前已绘制点数、视角参数。
5. 深色主题（背景 #0a0a0f），移动端触摸拖拽可用。

本题观察

  • 撞色配色出奇一致：两边都选 #0a0a0f 作主背景、紫色为 accent。Claude 用蓝→紫→洋红连续渐变（题目要求的那组），V4-Pro 也按题做了渐变。
  • 渲染策略Claude 做了"按颜色段批量 stroke"优化——连续相同颜色的线段合并进一个 Path 再 stroke，减少 strokeStyle 切换；V4-Pro 路径未看源码不展开。两边都用了 shadowBlur 发光。
  • 交互都正确实现拖拽 + 滚轮 + 触屏。Claude 的面板在左上小卡片，V4-Pro 的在顶部居中 pill 栏——两种主流选择。
  • 思维链密度最高V4-Pro 本题 8 093 tok 思维链，占比 54 %，三题中最高。合理：RK4 公式 + 旋转矩阵 + 坐标系映射 + 性能折衷都需要显式推导。
  • 体量Claude 9.6 KB / V4-Pro 34 KB（约 3.5 倍）。Claude 的做法是"尽可能让代码 terse"，V4-Pro 偏"每个职责都单独一段 CSS / 函数"。

本题观察

  • 品味差异最明显Claude 选"冷色极简"——白/灰底，工作态红 #ef4444，休息态绿 #10b981，长休息蓝 #3b82f6，28px tabular-nums 大钟，偏"Notion / Linear"风。V4-Pro 选"咖啡店温暖感"——米白 #f7f5f2 + 深啡文字 #2c2416 + 红砖色工作态 #d94e3c，非常"专注向 app"的调性。两种都好看，取向截然不同。

结论

V4-Pro 的前端代码能力是真的"能打"。三题都一次通过 finish_reason=stop，所有功能点基本覆盖，视觉取向也有自己明确的主张（尤其 T3 的咖啡店美学很有辨识度）。这不是"玩具级"的水平——是可以直接塞进一个 side project 的水平。

但两个代价要清楚地摆在桌上：一是 延迟——单发一题 7–8 分钟同步等待，不能做交互式开发流，必须做成"submit → 异步回来看"的工作流；二是 体量——V4-Pro 的输出普遍是 Claude 的 4–7 倍，大多花在 CSS 设计 token 展开和"按组件切段"的组织上。如果你追求的是 terse、可读、便于后续人工维护的代码，V4-Pro 的输出需要再精简一遍。

思维链是 V4-Pro 最大的隐形成本。本轮合计 23 181 reasoning tokens ≈ 47.7 % 的输出预算花在推理上。这部分正常计费，但对用户不可见（除非你主动读 reasoning_content）。如果纯按"可见代码字符 / 花钱 tokens"算性价比，V4-Pro 大概是把约一半的钱买了"看不见的思考"——这不是 bug，是推理模型的共性，但需要在成本模型里预留。

品味维度有意思。三题里有两题两家撞色（T2 都深色紫、T1 都深色暖色 accent），但 T3 番茄钟完全走向两个方向——Claude 冷色 Notion 风，V4-Pro 咖啡店米白暖红。同样的 prompt 能出如此差异的审美取向，说明大模型的"设计肌肉记忆"这件事是真实存在的。如果你给设计自由度不抠细节，V4-Pro 会帮你补一套完整的视觉语言；如果你自己有审美主张，Claude 的简洁更好往上叠加。

什么时候选谁：需要"即时交互开发、代码精简、自己有审美主张"时用 Claude；需要"一次性产出完整 side project、接受 7 分钟等待、愿意给模型设计自由"时用 V4-Pro。两者不是替代关系，更像两种不同的工作模式。
