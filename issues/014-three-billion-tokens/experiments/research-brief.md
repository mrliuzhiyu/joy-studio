# 014 · 超过 30 亿 Token 与产品认知 · research brief

> 本期不做工程复盘。单日峰值 33.5 亿 Token、单次任务最长 11 小时 9 分，只作为认知问题的入口。正文讨论 AI 如何从上下文中临时重建产品，以及怎样把临时理解变成持久、可验证的外部认知。

## 可复核的 Token 样本

从一条本地 AI 会话日志读取到累计值：

| 指标 | Token |
|---|---:|
| 总 Token | 123,162,350 |
| 输入 | 122,773,632 |
| 其中缓存输入 | 119,655,424 |
| 输出 | 388,718 |
| 其中推理输出 | 97,711 |

计算：

- 输入占总 Token 约 99.68%。
- 缓存输入占全部输入约 97.46%。
- 输出占总 Token 约 0.32%。
- 该样本不是“30 亿”总量的完整分解，只能用于说明 Token 去向的结构。

截图可直接确认：

- 峰值 Token 数为 33.5 亿，日历悬浮信息显示 7 月 17 日使用了 33.5 亿个 Token。
- 最长任务时长为 11 小时 9 分。

面板统计口径仍需要区分：

- 是否为单日账号总量。
- 是否包含缓存读取。
- 是否包含子任务、工具输出或多模型汇总。
- 同一输入被多个会话重复读取时如何计数。

## 认知模型

AI 没有天然连续的产品经验。每次新任务都要从当前上下文恢复一份临时世界模型。恢复材料来自四类外部事实：

- 规格：提供意图、目标与非目标。
- 代码：提供当前结构、状态与实际边界。
- 测试：提供已经被固定的不变量。
- 运行反馈：提供真实用户、平台与环境中的结果。

上下文窗口不是长期记忆。缓存能降低重复读取成本，却不能保证不同会话形成相同解释。真正稳定的认知必须在对话以外存在。

## 三种真相

产品认知需要同时解释：

1. 意图真相：产品为何存在，要改变什么，不解决什么。
2. 结构真相：实体、状态、职责与副作用如何组织。
3. 运行真相：真实用户和环境进入后，实际发生了什么。

三者可以继续压缩成四类长期事实：目标、状态、边界、证据。没有反证条件的理解只是一种解释，能够说明什么现象会证明自己错误，才是可工作的认知。

## 认知暴露与反事实

实现以前，先要求 AI 说清：

- 这次变化对应哪个用户结果。
- 涉及哪些实体与状态。
- 允许跨越哪些边界。
- 哪些不变量不能被破坏。
- 用什么证据可以证明实现失败。

深度理解不等于复述文档，而是能够稳定回答反事实问题：绕过状态会怎样，外部失败会传播到哪里，删除边界会泄露什么认知，测试全绿后还有什么真实结果未被观察。

## 因果拆解

拆文件不等于解耦。真正的单点是闭合因果单元：有明确输入，只拥有自己的状态，通过显式输出影响后续，失败留下可处理结果，并明确自己不应该知道什么。

单点之间通过可版本化、可检查、可重放的产物，以及可拒绝、可恢复、可审计的状态迁移连接。这样才能限制变化与故障传播的距离。

## 点、线、面证据

- 点：证明局部因果是否稳定，失败是否留在边界内。
- 线：证明状态顺序、时间连续性与中断恢复是否成立。
- 面：证明用户、平台、权限、网络和真实数据同时进入后，产品结果是否成立。

三种证据不能互相替代。测试全绿只能证明已经写下来的约束没有被破坏，不能证明所有重要约束都已经被写下来。

## 可以下的判断

- Token 不是代码产量，更接近模型重建认知时占用的带宽。
- 高输入占比说明大量工作发生在读取、关联、审查和验证中，但不能据此断言所有消耗都有价值。
- 真正减少重复 Token 的方法不是只缩短提示词，而是把验证后的认知写入规格、状态模型、接口、测试和运行回执。
- 上下文关闭后仍然存在的约束与证据，才是系统真正拥有的认知。

## 不可以下的判断

- 不能把 30 亿 Token 写成 30 亿输出 Token 或同等规模的成果。
- 不能用 Token 与代码行数的比值衡量模型效率。
- 不能用单条样本推断全部用量结构。
- 不能把更长上下文直接等同于更深理解。
