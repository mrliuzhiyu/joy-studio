# Relio 实验 · 代码生成说明与人工文档对照

## 实验方法

实验对象：Joy 的公开仓库 [mrliuzhiyu/Relio](https://github.com/mrliuzhiyu/Relio)。

代码版本：`703f137a9bb7eb395d5e61746d29cefa45c349be`，最后提交于 2026-04-20。

步骤：

1. 第一轮屏蔽 `docs/`，只读取源代码、配置、数据库迁移和路由。
2. 生成项目概览、架构、数据流、接口和运行方式，结果见 [relio-generated-from-code.md](relio-generated-from-code.md)。
3. 第二轮读取 `docs/ARCHITECTURE.md`、`docs/PRD.md`、`docs/project_plan.md` 和 `docs/prompt.md`。
4. 用当前代码逐项判断人工文档与生成说明的准确性，并记录双方无法替代的内容。

这不是模型横评。实验只回答一个问题：当代码和文档描述同一个系统时，哪一边更接近当前事实；哪些信息根本不在代码里。

## 代码生成说明更准确的地方

| 事实 | 当前代码 | 人工文档 | 结果 |
|---|---|---|---|
| 解题模型 | 六个：Qwen3 VL ×3、Llama 4、Pixtral、Grok 4 | 四个：Gemini、Claude、GPT-4o、Qwen 2.5 VL | 人工文档已过期 |
| 仲裁模型 | Qwen3 VL 235B Thinking | Gemini 2.5 Pro | 人工文档已过期 |
| 拍题完成后的保存方式 | `/analyze` 内自动上传图片并写库 | 用户在对比页确认后 `POST /mistakes` | 人工文档已过期 |
| 前端读取 SSE 的方式 | `fetch` + `ReadableStream`，支持 POST 和授权头 | `EventSource` 示例 | 人工文档与实现不符 |
| 用户身份 | Supabase 匿名登录 + JWT；业务表按 `user_id` 隔离 | 初版 Schema 没有 `user_id` | 人工文档漏掉后续迁移 |
| 后端 Schema 位置 | 集中在 `schemas/models.py` | 文档写成四个独立文件 | 目录说明已过期 |
| 当前页面流向 | 拍题完成后进入错题详情；另有 `/compare/:mistakeId` | 统一先进入 `/compare`，再确认保存 | 人工文档描述旧流程 |
| 当前实施状态 | 拍题、错题、报告、训练、组卷、家长分享均已有后端代码 | `project_plan.md` 仍写“Phase 1 准备中” | 计划文档严重落后 |

这些都是“系统现在是什么”的问题。代码生成说明直接读取当前实现，所以没有继承旧文档中的四模型、旧接口和旧页面流程。

## 人工文档不可替代的地方

| 信息 | 代码能否恢复 | 人工文档提供的内容 |
|---|---|---|
| 谁付钱、谁使用 | 只能猜到面向小学生 | 家长是付费方，3–6 年级学生是使用方 |
| 为什么做这个产品 | 只能看到功能 | 不只给答案，而是诊断为什么反复犯错 |
| 市场定位 | 无法确认 | 与作业帮、小猿搜题和线下家教的差异 |
| 商业模式 | 只有未启用的订阅字段 | 免费版、月卡、学期卡及定价设想 |
| 成功标准 | 无法推断 | 周活、留存、付费转化、L3 触发率等目标 |
| 明确不做什么 | 很难区分“没做”与“不想做” | 作文、口语、知识图谱、小程序化等范围边界 |
| 设计意图 | 能看到颜色和组件，不能知道原因 | 学生应感到被理解，家长应感到专业可信 |
| 历史决策 | 只能看到最终残留 | 产品从英语单科扩展到全学科的过程 |

这些不是多读几遍代码就能恢复的信息。代码保存了选择的结果，没有保存当时有哪些候选、为什么选这个、未来还想往哪里走。

## 人工文档还有一种特殊价值

代码生成说明可以发现完整运行需要 Supabase，但无法直接给出所有本地初始化步骤。人工架构文档保留了端口、环境变量和启动设想，哪怕其中一部分已经过时，仍能补足代码没有显式表达的操作上下文。

这说明边界也不能简单画成“代码都对、文档都错”。准确的关系是：

- 代码最适合回答当前实现事实。
- 测试和运行结果最适合验证行为事实。
- 人工文档最适合保存意图、边界、取舍和操作上下文。
- AI 可以从代码生成前两类的可读视图，但无法凭空补出最后一类。

## 实验暴露出的另一个问题

人工文档并非完全没人更新。`ARCHITECTURE.md` 的日期是 4 月 17 日，代码最后提交是 4 月 20 日，两者只差三天，关键事实已经发生大面积偏移。

文档腐烂不一定需要半年。只要模型、接口和页面流程连续调整，三天就够了。AI 编程把实现速度继续推高后，靠人手动追着同步的成本只会更高。

## 暂定结论

Relio 支持第 011 期的核心判断：

> 描述系统现状的文档，应该尽量从代码、测试和运行状态生成；表达产品意图、约束和取舍的文档，仍然由人维护。

AI 没有让文档消失。它让“人工复制一遍代码已经表达过的事实”变得越来越没有必要。
