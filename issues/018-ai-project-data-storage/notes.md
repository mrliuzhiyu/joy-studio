# 018 · 决策快照

- 标题：AI 写的项目，数据到底该放在哪里？
- 钩子：本地注册、上传都正常，第二次部署后用户记录和文件一起消失。
- 核心观点：代码可以被重新构建，用户数据必须拥有独立于代码的生命周期；AI 时代不是换一套数据库，而是把传统数据纪律变成机器可读、可验证、受权限限制的数据合同。
- 传统部分：程序与数据分离；关系约束和事务；DBA、变更单、发布窗口、最小权限与备份恢复；保留原则，替换低效的人工传递。
- AI 部分：结构变更频率大幅增加；迁移即代码；仓库成为数据结构事实源；隔离环境验证；运行、迁移、备份账号分权；破坏性动作额外确认。
- 选型边界：SQLite 与 PostgreSQL 按数据位置、应用实例和并发写入判断，不按固定用户人数；文件进入对象存储；缓存和向量属于可重建派生数据。
- 配图：运行环境与数据生命周期分离；SQLite/PostgreSQL 判断路径；AI 数据变更进入生产的安全闭环；横版与方形安全裁切头图。
- 视觉定稿：采用书刊工程插图语言；暖白背景、墨黑、灰与极浅暖灰；不使用圆角卡片、阴影、状态灯、盾牌、彩色成功/失败线或对称 SaaS 流程面板。
- 划界：010 已讨论向量数据库与 PostgreSQL 的行业选型，本篇只把向量视为派生数据的一种，不重复行业趋势；017 已解释第一次部署，本篇深入数据的保存、变更、权限和恢复。
