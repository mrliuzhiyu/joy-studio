## 一、voice 五条达标度(7/10)

**②能中文就中文:达标。** 留英文的都是专名(Postgres / pgvector / HNSW / Pinecone / Supabase / Neon / SQL / RAG 等),常见词都中文(向量 / 索引 / 检索 / 召回 / 过滤 / 事务 / 备份)。无堆英文问题。

**③短句说人话:达标。** 通篇短句,口语顺。如"少一个独立部署、一套凭据、一块监控面板、一个会半夜单独宕掉的服务"节奏好。

**④少破折号、少装饰双引号:基本达标,有零星残留。**

- 全文未见装饰性双引号包概念(✅),也几乎没有破折号当连接。唯一可留意:notes 里点名要躲的破折号,draft 里没犯。这条过。

**⑤不说教:两处复发,是本维度扣分主因。**
- **P0 · 04 章末尾决策口诀化**:原句"默认用 Postgres,直到撞上一个能量化的、具体的墙(延迟超标、内存扛不住、过滤场景做不动),才迁。认真做过选型的人,最后大多走的是这个顺序。专门的向量库不是错的选择,它是撞到墙之后的选择,而不是第一步。"——"认真做过选型的人最后大多这么做"这个句式,**恰好是 voice memory 反面例子里点名要改的那一句的同款**(memory 原文:"第一别用综合分…… → 改成'认真测过的人最后大都这么做'的叙述")。这里虽不是编号清单,但"不是错的选择,它是撞到墙之后的选择,而不是第一步"是对仗格言式收束,带训导腔。

## 八、标题候选(主推 A,理由如下)

draft 顶部四个候选:
- **A:向量数据库火了两年,大家又搬回了 Postgres** — **推荐**。叙事直白(谁都看得懂是什么事),有动作("搬回"),延续 005"绕一圈回到朴素"的成功气质。唯一小风险:"火了两年""又搬回"略带反转戏剧性,但程度可接受,不算标题党。
- B:做 AI 应用,你多半不需要专门的向量数据库 — 最实用,但"你多半不需要"是直接对读者下判断 + 略带劝告腔,且与 Encore 原标题几乎雷同(显得像翻译),独立性弱。
- C:先别急着上向量数据库 — 最短,但"先别急着"是劝告口吻,voice 第五条忌说教,标题就带训导腔,不推荐。
- D:AI 没催生新数据库,反而把大家送回了 Postgres — 母题最大但偏抽象,"没催生新数据库"读者要想一下才懂,不如 A 直白。

**结论:A 最合规也最直白,采用 A。** 若想再降一点戏剧性,可微调为"向量数据库火了两年,大家又用回了 Postgres"("用回"比"搬回"更轻),属可选。
